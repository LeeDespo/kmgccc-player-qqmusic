# kmgccc_player 2.3.1 + QQMusic 1.1.0

给 [kmgccc_player](https://github.com/kmgcc/kmgccc_player) 加装的 QQ 音乐在线音源补丁。
本仓库 = **上游 2.3.1 + 一份可审计的变更集**（`modules/` 新文件 + `patches/` 对上游文件的 diff +
`removals.txt` 要删掉的上游文件），应用于未改动的上游源码即得完整功能。

- 基线：`b0de7aa6`（kmgccc_player 2.3.1）
- 补丁版本：`1.1.0`（应用内 QQ 音乐设置 → Helper 组件 → 「本功能版本」）
- 验证：干净的上游检出上重放补丁 → 构建成功 → 434 项单元测试通过 → 应用可启动

## 附件

| 附件 | 说明 |
|---|---|
| `…-arm64.dmg` | 打好补丁的应用（Apple Silicon，macOS 26+）。ad-hoc 签名，首次打开需放行一次 |
| `…-patch.tar.gz` | 补丁包：自己从上游构建，或把功能搬到别的上游版本 |
| `…-component.tar.gz` | **数据组件包**（`qqmusic-helper-next` + `aria2-next` + 替换说明）。接口失效时可只换它，不必重装应用 |

## 新增

- **Aria2 Next 下载引擎**：随组件发布、按需拉起，多连接分块、断点续传、并发与限速由它负责。
  设置里可调状态/重启/分块/连接数/并发/最小分块/限速/**RPC 端口**，改数字即时生效。
- **下载清单**：工具栏独立的进度框（有任务才出现），列出**整个选择**（歌名-歌手 + 文件名 + 实时进度），
  分段查看**下载中 / 失败 / 完成**，可单个或全部暂停 / 继续 / 取消（取消同时删临时文件）。
- **限流总闸与可配置熔断**：可设"多少秒内最多多少次请求"，超出排队而非丢弃；熔断参数直达组件。
- **逐字歌词**：下载的歌曲带词级时间，播放时逐字高亮（数据在 QQ 音乐的加密路上，
  组件内解密并转成宿主认识的格式）。
- **更新组件**入口：设置里一键查看替换步骤、跳到 Release 页面或打开目录。

## 修复

- 预下载只下一首、随机播放没有下一首（取流走了 web 档案，票据取不到）。
- 喜欢按钮点不动（组件要数字 songId，应用只有 songMid）。
- 歌手页从曲目行进入时没有头像与信息；搜索页歌单没有封面；切换搜索分段会跳回顶部。
- 批量下载恒显示 0/1、点下载后不退出选择模式、并发设置无效。
- 重启下载引擎会让任务卡死；关注的歌手因缺少 `encrypt_uin` 读不到。
- 专辑页只能看到第一页、「全选」只覆盖已加载的行（专辑接口本就报总数，组件丢掉了它）。

## 删除

- **Python helper**（含解释器与 `qqmusic-api-python`，约 56 MB）及其构建脚本。
- 应用内的第二套取数实现（`QQMusicWebAPI`）与"两条通道"机制，连同设置页「在线内容 → 通道」分区。

## 值得额外说明

在线数据原有两个来源（Python helper + 应用内 HTTP 客户端）。同一能力两份实现时，"兜底"掩盖的是
行为差异，落库与缓存判断还得同时考虑两者。现在只剩**一个数据组件**（Rust，约 2.4 MB）：
读取、登录、限流、熔断在它内部，下载字节由它拉起的 Aria2 Next 搬运。
**上游接口变化时换这几个文件即可，不必重建应用。**

## 安装要点

1. 拖进「应用程序」。首次打开会被 Gatekeeper 拦一次（**不是**"已损坏"）：
   `xattr -dr com.apple.quarantine /Applications/kmgccc_player.app`，或到
   系统设置 → 隐私与安全性 → 仍要打开。
2. 侧边栏「QQ 音乐」→ 手机扫码登录。
3. **在线下载需要「托管」资料库**（原位引用的资料库只能浏览）。
4. 选择单独更新组件时，复制到 `…/QQMusicHelperNext/` 后**必须** `xattr -cr` **并**
   `codesign --force --sign -`，两步都做——只清属性仍会被系统杀掉（退出码 137，无输出）。
